Это практическое дополнение к посту в телеграм-канале про то, почему CUPED – это старая добрая ANCOVA. Там теория, а здесь пошаговый разбор с кодом на R и Python: как применить CUPED к A/B-тесту и не наступить на типичные грабли.

Данные синтетические, но устроены как настоящая выручка: большинство пользователей ничего не покупают, у платящих длинный хвост, а у части пользователей нет истории до теста. Код на R и Python читает одни и те же CSV-файлы, поэтому цифры во вкладках совпадают.

1. Данные

Онлайн-библиотека, тест нового экрана оплаты, по 2 недели на тест. Данные лежат в двух файлах:

  • cuped_experiment.csv – сам эксперимент, 40 000 пользователей;
  • cuped_history.csv – те же метрики за прошлый период, до запуска теста. Понадобится в шаге 3.

Колонки:

  • group – контроль или тест;
  • is_new – пользователь пришёл недавно, истории до теста у него нет (таких 20%);
  • rev_pre – выручка за 2 недели до теста, у новых пользователей пропуск;
  • revenue – выручка за 2 недели теста, это наша метрика;
  • rev_week1 – выручка за первую неделю теста. Понадобится в шаге 7, чтобы показать, как делать не надо.

Истинный эффект в тестовой группе: +3% к выручке.

NoteКак сгенерированы данные

Связь между «до» и «во время» задаёт скрытая склонность пользователя платить (activity): кто платил раньше, скорее заплатит и сейчас. В реальных данных её не видно, у нас есть только выручка. Генератор понадобится ещё раз в шаге 8, для симуляции.

  • R
  • Python
generate_data <- function(n = 40000, effect = 0.03, seed = 42) {
  set.seed(seed)
  tibble(
    user_id  = 1:n,
    group    = sample(c("control", "test"), n, replace = TRUE),
    is_new   = rbinom(n, 1, 0.2) == 1,   # нет истории до теста
    activity = rnorm(n)                  # скрытая склонность платить
  ) |>
    mutate(
      # предпериод: платил ли и сколько
      pay_pre   = rbinom(n, 1, plogis(-0.5 + 3 * activity)),
      rev_pre   = if_else(is_new, NA_real_,
                          pay_pre * exp(5 + 0.8 * activity + rnorm(n, 0, 0.5))),
      # период теста: та же склонность + эффект в тестовой группе
      pay       = rbinom(n, 1, plogis(-0.5 + 3 * activity)),
      revenue   = pay * exp(5 + 0.8 * activity + rnorm(n, 0, 0.5)) *
                  if_else(group == "test", 1 + effect, 1),
      # часть выручки теста, пришедшаяся на первую неделю
      rev_week1 = revenue * runif(n, 0.3, 0.7)
    ) |>
    select(user_id, group, is_new, rev_pre, revenue, rev_week1)
}

def generate_data(n=40_000, effect=0.03, seed=42):
    rng = np.random.default_rng(seed)
    activity = rng.normal(size=n)                     # скрытая склонность платить
    p_pay = 1 / (1 + np.exp(-(-0.5 + 3 * activity)))
    group = rng.choice(["control", "test"], size=n)
    is_new = rng.random(n) < 0.2                      # нет истории до теста

    # предпериод: платил ли и сколько
    pay_pre = rng.random(n) < p_pay
    rev_pre = pay_pre * np.exp(5 + 0.8 * activity + rng.normal(0, 0.5, n))
    rev_pre = np.where(is_new, np.nan, rev_pre)

    # период теста: та же склонность + эффект в тестовой группе
    pay = rng.random(n) < p_pay
    revenue = pay * np.exp(5 + 0.8 * activity + rng.normal(0, 0.5, n))
    revenue = revenue * np.where(group == "test", 1 + effect, 1)
    rev_week1 = revenue * rng.uniform(0.3, 0.7, n)    # часть выручки за первую неделю

    return pd.DataFrame({"user_id": np.arange(1, n + 1), "group": group, "is_new": is_new,
                         "rev_pre": rev_pre, "revenue": revenue, "rev_week1": rev_week1})
TipКак собрать такую таблицу из своих данных

Нужна одна строка на пользователя эксперимента. Главное правило: предпериод отсчитывается от момента, когда этот пользователь попал в тест, а не от даты старта теста. Набросок на SQL:

with exposure as (            -- первое попадание пользователя в тест
  select user_id, group_name, min(event_time) as exposed_at
  from ab_exposures
  where test_id = 'paywall_v2'
  group by user_id, group_name
)
select
  e.user_id,
  e.group_name as "group",
  -- метрика за период теста: от попадания в тест до конца теста
  coalesce(sum(case when p.paid_at >= e.exposed_at
                     and p.paid_at < '2026-10-01' then p.amount end), 0) as revenue,
  -- ковариата: такое же окно (14 дней) ДО попадания в тест
  coalesce(sum(case when p.paid_at >= e.exposed_at - interval '14 days'
                     and p.paid_at < e.exposed_at then p.amount end), 0) as rev_pre,
  -- нет истории: зарегистрировался позже начала окна предпериода
  u.registered_at > e.exposed_at - interval '14 days' as is_new
from exposure e
join users u using (user_id)
left join payments p using (user_id)
group by e.user_id, e.group_name, u.registered_at, e.exposed_at

Для новых пользователей rev_pre здесь получится 0, а не пропуск. Это нормально, если есть флаг is_new, дальше мы делаем ровно так же.

2. Готовим ковариату

Сначала договоримся о подготовке данных: ровно её же мы применим и к истории в шаге 3, и к самому тесту.

Новые пользователи. У них rev_pre отсутствует. Выкидывать их нельзя: это часть эксперимента, и без них оценка эффекта будет про другую аудиторию. Стандартное решение, оно же описано в оригинальной статье про CUPED: заполнить пропуск константой (например, нулём) и добавить индикатор «нет истории» как отдельную ковариату. Константа может быть любой, индикатор всё равно отделит этих пользователей.

Выбросы. Пара пользователей с огромной выручкой раскачивает и среднее, и саму оценку θ. Поэтому до расчёта CUPED метрику и ковариату винсоризируют: обрезают по высокому перцентилю. Порог считаем по объединённым данным контроля и теста, а не отдельно по группам, иначе группы будут обработаны по-разному.

Warning

Винсоризация меняет метрику: теперь это не «выручка», а «выручка с обрезанными китами». Порог нужно зафиксировать до анализа, а не подбирать по результату.

  • R
  • Python
winsorize <- function(x, p = 0.995) pmin(x, quantile(x, p, na.rm = TRUE))

prepare <- function(df) {
  df |>
    mutate(
      revenue_w = winsorize(revenue),
      x_pre     = coalesce(winsorize(rev_pre), 0)   # пропуск у новых → 0, флаг is_new уже есть
    )
}

df <- prepare(df)
def winsorize(x, p=0.995):
    return np.minimum(x, np.nanquantile(x, p))

def prepare(df):
    df = df.copy()
    df["revenue_w"] = winsorize(df["revenue"])
    df["x_pre"] = winsorize(df["rev_pre"]).fillna(0)   # пропуск у новых → 0, флаг is_new уже есть
    return df

df = prepare(df)

3. До запуска теста: есть ли смысл в CUPED

CUPED умножает дисперсию на \(1 - \rho^2\), то есть снижает её на \(\rho^2\), где \(\rho\) – корреляция метрики с ковариатой. Решать, стоит ли игра свеч, нужно до запуска теста, а не по его результатам. Иначе это то же подглядывание: попробовали с CUPED и без, выбрали, где p-value меньше.

Поэтому берём историю: те же метрики за прошлый период. Например, выручку пользователей за 2 недели месяц назад (как будто это «период теста») и за 2 недели до них (как будто это «предпериод»). Групп и эффекта в истории нет. Прогоняем историю через ту же функцию prepare() и смотрим:

  • какую долю дисперсии метрики объясняет ковариата. Это и есть ожидаемое снижение дисперсии. Для одной ковариаты оно равно \(\rho^2\), для нескольких (Multi-CUPED) это \(R^2\) регрессии;
  • какой MDE получится с CUPED и без него при запланированном размере выборки.
  • R
  • Python
history <- read_csv("data/cuped_history.csv") |> prepare()

rho_old  <- with(filter(history, !is_new), cor(x_pre, revenue_w))
r2_cuped <- cor(history$x_pre, history$revenue_w)^2
r2_multi <- summary(lm(revenue_w ~ x_pre + is_new, data = history))$r.squared

# MDE для двустороннего теста: alpha = 5%, мощность 80%
mde <- function(sd, n_per_group, alpha = 0.05, power = 0.8) {
  (qnorm(1 - alpha / 2) + qnorm(power)) * sd * sqrt(2 / n_per_group)
}
n_per_group <- 20000
sd_y <- sd(history$revenue_w)
mu_y <- mean(history$revenue_w)

tibble(
  method             = c("t-test", "CUPED: x_pre", "Multi-CUPED: x_pre + is_new"),
  variance_reduction = c(0, r2_cuped, r2_multi),
  mde_relative       = mde(sd_y * sqrt(1 - variance_reduction), n_per_group) / mu_y
) |>
  mutate(variance_reduction = scales::percent(variance_reduction, accuracy = 1),
         mde_relative       = scales::percent(mde_relative, accuracy = 0.1)) |>

from scipy.stats import norm

history = prepare(pd.read_csv("data/cuped_history.csv"))

old = history[~history["is_new"]]
rho_old = old["x_pre"].corr(old["revenue_w"])
r2_cuped = history["x_pre"].corr(history["revenue_w"]) ** 2
r2_multi = smf.ols("revenue_w ~ x_pre + is_new", data=history.astype({"is_new": int})).fit().rsquared

# MDE для двустороннего теста: alpha = 5%, мощность 80%
def mde(sd, n_per_group, alpha=0.05, power=0.8):
    return (norm.ppf(1 - alpha / 2) + norm.ppf(power)) * sd * np.sqrt(2 / n_per_group)

n_per_group = 20_000
sd_y, mu_y = history["revenue_w"].std(), history["revenue_w"].mean()

}).assign(MDE=lambda d: mde(sd_y * np.sqrt(1 - d["Снижение дисперсии"]), n_per_group) / mu_y).round(3)

Что видно:

  • У пользователей с историей корреляция \(\rho \approx\) 0.67, это обещало бы снижение дисперсии на 45%. Но по всей аудитории выходит меньше, 33%: у новых пользователей предпериода нет, и для них CUPED ничего не даёт. Поэтому ожидаемый выигрыш нужно считать на всех пользователях, которые попадут в тест, а не только на «удобных».
  • Индикатор is_new добавляет немного: новые пользователи платят иначе, чем старые с нулевой выручкой в предпериоде.
  • MDE с CUPED заметно меньше. На практике это значит, что тот же тест можно провести быстрее или на меньшей выборке.

Если бы на истории получилось \(\rho \approx 0.2\)–\(0.3\), снижение дисперсии было бы 4–9%, и возиться с CUPED, скорее всего, не стоило бы.

4. Тест закончился: CUPED руками

Формула одна: \(Y_{cuped} = Y - \theta (X - \bar{X})\), где \(\theta = \text{Cov}(X, Y) / \text{Var}(X)\). Два важных момента:

  • θ считаем один на обе группы, по объединённым данным. Если считать отдельно в контроле и тесте, оценка эффекта становится смещённой.
  • Центрирование \(X - \bar{X}\) нужно только для того, чтобы среднее метрики не поменялось. На оценку разницы между группами оно не влияет.

Для сравнения посчитаем и разность «после минус до» (\(\theta = 1\)), про которую была ловушка в посте.

  • R
  • Python
theta <- cov(df$x_pre, df$revenue_w) / var(df$x_pre)

df <- df |>
  mutate(revenue_cuped = revenue_w - theta * (x_pre - mean(x_pre)),
         revenue_diff  = revenue_w - x_pre)

# t.test считает «контроль − тест», переворачиваем в «тест − контроль»
summarise_t <- function(tt, method) {
  tibble(method  = method,
         effect  = unname(diff(tt$estimate)),
         ci_low  = -tt$conf.int[2],
         ci_high = -tt$conf.int[1],
         p_value = tt$p.value)
}

t_plain <- t.test(revenue_w ~ group, data = df)
t_diff  <- t.test(revenue_diff ~ group, data = df)
t_cuped <- t.test(revenue_cuped ~ group, data = df)

bind_rows(summarise_t(t_plain, "t-test"),
          summarise_t(t_diff,  "Разность «после минус до»"),
          summarise_t(t_cuped, "CUPED")) |>
  mutate(variance_vs_ttest = ((ci_high - ci_low) / (ci_high[1] - ci_low[1]))^2) |>
  knitr::kable(digits = 3)

is_test = df["group"] == "test"
theta = np.cov(df["x_pre"], df["revenue_w"])[0, 1] / df["x_pre"].var()
df["revenue_cuped"] = df["revenue_w"] - theta * (df["x_pre"] - df["x_pre"].mean())
df["revenue_diff"] = df["revenue_w"] - df["x_pre"]

def welch(col):
    t, c = df.loc[is_test, col], df.loc[~is_test, col]
    res = stats.ttest_ind(t, c, equal_var=False)
    ci = res.confidence_interval()
    return {"effect": t.mean() - c.mean(), "ci_low": ci.low, "ci_high": ci.high, "p_value": res.pvalue}

out = pd.DataFrame({"t-test": welch("revenue_w"),
                    "Разность «после минус до»": welch("revenue_diff"),
                    "CUPED": welch("revenue_cuped")}).T
out["variance_vs_ttest"] = ((out.ci_high - out.ci_low) / (out.ci_high.iloc[0] - out.ci_low.iloc[0])) ** 2
out.round(3)

Эффект +3% в данных заложен, но обычный t-тест его не видит (p = 0.22): выручка слишком шумная. Оценка CUPED почти та же, а доверительный интервал заметно уже: дисперсия уменьшилась на 35%, p-value снизился с 0.22 до 0.09. Это близко к тому, что мы ожидали по истории в шаге 3 (33%), так что прогноз на истории работает.

Разность «после минус до» тоже немного помогла (дисперсия 75% от t-теста), потому что корреляция здесь больше 0.5. Но CUPED всё равно точнее. При слабой корреляции разность оказалась бы хуже обычного t-теста.

Значимым эффект не стал и с CUPED. Окажется ли он значимым на одном конкретном датасете – дело случая: CUPED не гарантирует «прокрас», а повышает его вероятность. На симуляции в шаге 8 мощность растёт примерно с 39% до 55%, то есть такой эффект CUPED будет находить заметно чаще.

TipОтносительный эффект

Продакты обычно спрашивают «на сколько процентов». Делить разницу нужно на среднее исходной (не скорректированной) метрики в контроле: здесь это 2.3%. Для строгого доверительного интервала относительного эффекта нужен дельта-метод или бутстреп.

5. То же самое через регрессию

CUPED – это регрессия revenue ~ group + x_pre, посчитанная в два шага. В одну строку это удобнее, а заодно сразу получаются робастные стандартные ошибки и можно добавить сколько угодно ковариат.

  • R
  • Python
# CUPED = ANCOVA
m_cuped <- lm_robust(revenue_w ~ group + x_pre, data = df)

# Multi-CUPED: + индикатор новых пользователей
m_multi <- lm_robust(revenue_w ~ group + x_pre + is_new, data = df)

# поправка Лина: взаимодействие с центрированными ковариатами
m_lin <- lm_lin(revenue_w ~ group, covariates = ~ x_pre + is_new, data = df)

bind_rows(
  tidy(m_cuped) |> mutate(model = "CUPED: ~ group + x_pre"),
  tidy(m_multi) |> mutate(model = "Multi-CUPED: + is_new"),
  tidy(m_lin)   |> mutate(model = "Lin: group * (x_pre + is_new)")

Оценка из первой модели совпадает с CUPED руками с точностью до третьего знака. Небольшая разница есть потому, что в CUPED θ считается по объединённым данным, а в регрессии наклон оценивается с учётом группы. Индикатор is_new добавляет ещё немного точности, как и обещала история.

Какую модель брать:

  • Сплит 50/50 – подойдёт любая из трёх, разница будет минимальной.
  • Неравный сплит (например, 10/90) и эффект может быть разным у разных пользователей – берите модель Лина. Модель без взаимодействия в таком случае может оказаться даже хуже обычного t-теста.
  • Стандартные ошибки всегда робастные (HC): lm_robust() в R, cov_type="HC2" в Python.

6. ARPPU: то же самое на платящих

До сих пор метрикой была выручка на пользователя (ARPU). С ARPPU (выручка на платящего) работает тот же пайплайн, только на подвыборке платящих: рандомизация по пользователям, у каждого платящего одно значение, так что обычный t-тест и CUPED применимы как есть. Отличий три.

1. Выигрыш от CUPED нужно пересчитать на истории, по платящим. Без нулей корреляция с предпериодом обычно ниже, чем у ARPU: часть «объяснения» у ARPU давал сам факт платил/не платил. Порог винсоризации тоже считаем по платящим, поэтому заново прогоняем prepare() на подвыборке.

2. Новые пользователи среди платящих. Их доля среди платящих может заметно отличаться от доли во всей аудитории (у нас она такая же, около 20%, но в реальных данных бывает по-разному). Индикатор is_new оставляем.

3. Подвыборка определяется после воздействия. «Платящий» считается по периоду теста. Если фича меняет конверсию в оплату, платящие в контроле и тесте – уже разные по составу люди, и сравнение ARPPU становится сравнением разных аудиторий. Это проблема и для t-теста, и для CUPED. Поэтому сначала проверяем конверсию.

Important

Ковариата должна быть посчитана строго до того, как пользователь попал в эксперимент. Если пользователи входят в тест постепенно, предпериод отсчитывается от момента входа каждого пользователя, а не от даты старта теста.

8. Проверяем на симуляции

Перед тем как внедрять CUPED в пайплайн, стоит прогнать его на A/A и A/B-симуляциях: ошибка первого рода должна остаться около 5%, а мощность должна вырасти. Генерируем 1000 датасетов без эффекта и 1000 с эффектом +3% и на каждом прогоняем тот же пайплайн.

analyze <- function(df) {
  df <- prepare(df)
  theta <- cov(df$x_pre, df$revenue_w) / var(df$x_pre)
  df <- mutate(df, revenue_cuped = revenue_w - theta * (x_pre - mean(x_pre)))

    method  = c("t-test", "CUPED"),
    p_value = c(t.test(revenue_w ~ group, data = df)$p.value,

def analyze(df):
    df = prepare(df)
    y, x = df["revenue_w"], df["x_pre"]
    theta = np.cov(x, y)[0, 1] / x.var()
    y_cuped = y - theta * (x - x.mean())
    t = df["group"] == "test"
    return {
        "t-test": stats.ttest_ind(y[t], y[~t], equal_var=False).pvalue,
        "CUPED":  stats.ttest_ind(y_cuped[t], y_cuped[~t], equal_var=False).pvalue,
    }

Здесь каждый прогон генерирует новые данные, а генераторы случайных чисел в R и Python разные, поэтому цифры во вкладках немного отличаются. Выводы одни и те же. Если на ваших данных CUPED в A/A даёт заметно больше 5%, где-то ошибка: чаще всего ковариата посчитана не до теста.

gen_revenue <- function(n, rho, effect = 0) {
  z_pre  <- rnorm(n)
  z_post <- rho * z_pre + sqrt(1 - rho^2) * rnorm(n)
  tibble(x_pre = exp(1 + 0.8 * z_pre),
         y     = exp(1 + 0.8 * z_post) * (1 + effect))
}

post_experiment <- function(n, rho, effect) {
  d <- bind_rows(gen_revenue(n, rho)         |> mutate(group = "control"),
                 gen_revenue(n, rho, effect) |> mutate(group = "test"))
  theta <- cov(d$x_pre, d$y) / var(d$x_pre)
  d <- mutate(d, y_change = y - x_pre, y_cuped = y - theta * (x_pre - mean(x_pre)))
  welch <- function(f) { r <- t.test(f, data = d); tibble(p_value = r$p.value, se = r$stderr) }
  bind_rows(welch(y ~ group)        |> mutate(method = "t-test"),
            welch(y_change ~ group) |> mutate(method = "Разность"),
            welch(y_cuped ~ group)  |> mutate(method = "CUPED")) |>
    mutate(corr = cor(d$x_pre, d$y))
}

rng = np.random.default_rng(2026)

def gen_revenue(n, rho, effect=0.0):
    z_pre = rng.normal(size=n)
    z_post = rho * z_pre + np.sqrt(1 - rho**2) * rng.normal(size=n)
    return np.exp(1 + 0.8 * z_pre), np.exp(1 + 0.8 * z_post) * (1 + effect)

def post_experiment(n, rho, effect):
    xc, yc = gen_revenue(n, rho)
    xt, yt = gen_revenue(n, rho, effect)
    x, y = np.r_[xc, xt], np.r_[yc, yt]
    theta = np.cov(x, y)[0, 1] / x.var(ddof=1)
    out = {}
    for method, (a, b) in {"t-test":   (yc, yt),
                           "Разность": (yc - xc, yt - xt),
                           "CUPED":    (yc - theta * (xc - x.mean()), yt - theta * (xt - x.mean()))}.items():
        res = stats.ttest_ind(b, a, equal_var=False)
        out[method] = (res.pvalue, a.var(ddof=1) / n + b.var(ddof=1) / n)
    return out, np.corrcoef(x, y)[0, 1]
